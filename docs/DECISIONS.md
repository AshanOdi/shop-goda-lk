# Decisions

| Date | Decision | Reason |
| --- | --- | --- |
| 2026-10-09 | The repo root is the `Ape Kade` folder; the package is named `sidadiya`. The app was scaffolded in a `sidadiya/` subfolder and moved up. | npm package names can't contain spaces or capitals, so `create-next-app` can't run directly in `Ape Kade`. |
| 2026-10-09 | Next.js 16.4.0, React 19.3, Tailwind CSS 4, ESLint 9 (from `create-next-app@latest`). | Latest stable versions at project start (SPEC 3). |
| 2026-10-09 | Stay on pnpm 9.15.9 (pinned via `packageManager` in `package.json`); don't upgrade yet. | A major-version jump to pnpm 12 mid-setup risks lockfile changes; we'll revisit after M0. |
| 2026-10-09 | `CLAUDE.md` imports `AGENTS.md` (generated by Next.js). | Next.js 16 keeps version-specific guidance in `AGENTS.md` and its bundled docs; this makes sure it is read. |
| 2026-10-10 | Drizzle ORM 0.45 / drizzle-kit 0.31 (npm `latest`), not the 1.0 release candidate. | Stable versions for the money path; revisit when 1.0 is released. |
| 2026-10-10 | Postgres driver: `postgres` (postgres.js) with `prepare: false`. | Supabase recommends it with Drizzle; its transaction pooler doesn't support prepared statements. |
| 2026-10-10 | Local Postgres 17 in Docker (`compose.yaml`), user/password/db `sidadiya`. | Matches a current Supabase Postgres major version. Note: this user is a superuser and bypasses RLS; M1 adds a separate non-superuser app role (SPEC 5.6). |
| 2026-10-10 | `src/env.ts` uses plain zod 4. Only `DATABASE_URL` and `BETTER_AUTH_SECRET` are required; provider keys are optional and each provider checks its own keys when it is built. | SPEC 16: `pnpm dev` must work with only those two set. Requiring production keys in env.ts would also break `next build` in CI. |
| 2026-10-10 | `drizzle.config.ts` loads env files with `@next/env` instead of `dotenv`. | Same `.env.local` loading rules as Next.js, and one less dependency. |
| 2026-10-10 | Added `GET /api/health` (checks the database). | Gives M0 a way to prove the DB connection works; reused for uptime monitoring (SPEC 15). |
| 2026-10-10 | shadcn/ui with the `radix-nova` preset (Radix UI, Lucide icons, neutral base). Generated `src/components/ui` is excluded from Prettier. | Lucide is the SPEC 3 icon set. Keeping generated components as the CLI writes them makes future `shadcn add`/updates diff cleanly. |
| 2026-10-10 | shadcn's `--primary` and `--ring` use `--brand-maroon`; `--radius` is 12px. Brand colours are Tailwind utilities (`bg-brand-maroon`, `text-brand-ink`...). Dark-mode colours stay shadcn defaults until the dashboard (M1/M2). | SPEC 11 tokens; dark mode is a dashboard requirement. |
| 2026-10-10 | Inter via `next/font`; "Noto Sans Sinhala" and "Noto Sans Tamil" are listed only as CSS fallbacks, not loaded yet. | Phase 1 is English only; loading the Noto fonts now would slow buyer pages for nothing. Load them with the Phase 3 translations. |
| 2026-10-10 | next-intl 4 without i18n routing; locale fixed to `en` in `src/i18n/request.ts` (time zone `Asia/Colombo`). Don't call `getTranslations` inside `"use cache"` scopes; pass translated strings in as props instead. | Simplest setup for one language. A fixed locale doesn't read cookies or headers, so it works with Cache Components. |
| 2026-10-10 | `@types/node` ^22. | Matches the installed Node 22 and Vitest 5's peer dependency. |
| 2026-10-10 | The product is **Ape Kade** (identifier `apekade`), not Sidadiya. Renamed everywhere: docs, package name, database/user (`apekade`), env defaults (`mail.apekade.lk`, `TEXTLK_SENDER_ID=ApeKade`, `APEKADE_PAYHERE_*`), cookie `ak_src`. Earlier rows above that say `sidadiya` describe the state at that time. | Sidadiya is a separate business whose spec and ads were used as an example. |
| 2026-10-10 | Original Ape Kade look: maroon `#7A1F2B` primary, orange `#F08A24` call to action, peach/sand backgrounds (SPEC 11). `docs/brand/` ads are kept only as a feature reference; their name, colours, slogans and style must not be copied. | Our own identity; warm "local shop" feel; maroon gives 12:1 contrast with white, orange is always used with dark text. |
| 2026-10-10 | Domain `apekade.lk` is a placeholder via `NEXT_PUBLIC_APP_URL` / `EMAIL_FROM_DOMAIN`; UI reads the host from `env` rather than hard-coding it. | Availability not checked yet; changing domain must only need env changes. |
| 2026-10-10 | Playwright runs one `mobile` project: Chromium with a 390 × 844 viewport, touch and mobile mode. Locally it reuses `pnpm dev`; in CI it runs against `pnpm build` + `pnpm start`. | SPEC 13 phone viewport and production build. Chromium only for now to keep CI fast; WebKit (iPhone Safari) can be added before launch. |
| 2026-10-10 | One GitHub Actions job (`check`): install → `pnpm check` → build → Playwright, with a Postgres 17 service container. Action versions: checkout v7, setup-node v7, pnpm/action-setup v6, upload-artifact v7. | Simplest pipeline that covers SPEC 13; split into parallel jobs later if it gets slow. `db:migrate` is added to CI once the first migration exists (M1). |
| 2026-10-10 | `main` is protected on GitHub: changes go through a pull request and the `check` job must pass. | INSTRUCTIONS 1.4: `main` is always deployable; prevents accidental direct pushes. |
| 2026-10-10 | Hosting: Vercel (Hobby for now, Pro before pilot shops), functions pinned to `bom1` in `vercel.json`. One Supabase project in Mumbai (`ap-south-1`) serves as the **staging** database for preview and `main` deployments until launch, when a separate production project is created. | SPEC 3 region choice; Hobby is fine while building but is non-commercial. One staging DB keeps free-tier limits and setup simple. |
| 2026-10-10 | Deployed apps connect through Supabase's transaction pooler (port 6543) with `?sslmode=require`; postgres.js already uses `prepare: false`. | Serverless functions open many short connections; the pooler shares a few real ones. SSL encrypts traffic between Vercel and Supabase. |
| 2026-10-10 | Sentry (`@sentry/nextjs` v11) set up with the wizard, then changed: one shared `src/lib/sentry.ts` for browser/server/edge; Sentry starts only when `NEXT_PUBLIC_SENTRY_DSN` is set (so not in local dev or tests); `tracesSampleRate` 0.1; no Session Replay; `/monitoring` tunnel. | One place to change settings; free-tier quota; Replay records buyer screens (PII) and adds browser JS. |
| 2026-10-10 | Sentry privacy: `dataCollection` turns off user info, cookies, request bodies, query params, DB query data and stack variables (v11 collects all of these by default; `sendDefaultPii` is deprecated). `beforeSend` = `scrubEvent()`, which also deletes `user`/request body/cookies and redacts emails and Sri Lankan mobile numbers in messages. | CLAUDE.md: never log buyer phone, address or email; Sri Lanka PDPA. |
| 2026-10-10 | `SENTRY_DSN` renamed to `NEXT_PUBLIC_SENTRY_DSN`; added build-only `SENTRY_AUTH_TOKEN` (SPEC 16 updated). | The browser config needs the DSN, and only `NEXT_PUBLIC_*` variables reach the browser. The DSN is public by design; the auth token is secret and only used during `next build`. |
| 2026-10-10 | `global-error.tsx` still shows Next.js's default English error text. | It replaces the root layout, so the translations provider isn't available there; a translated, branded error page is part of M6 "error states everywhere". |
| 2026-10-10 | Better Auth tables are `users`, `sessions`, `accounts`, `verifications` (plural, snake_case columns), mapped to Better Auth's model names in the adapter config. Users keep Better Auth's boolean `email_verified` / `phone_number_verified` instead of SPEC 6.1's `*_verified_at` timestamps. | Better Auth reads and writes those exact boolean fields; fighting its schema would risk login bugs. Verification times can be added later if needed. |
| 2026-10-10 | Better Auth requires a unique email, but sellers sign up with a phone only. Until they add a real email, `users.email` holds a placeholder `<digits>@phone.invalid` (the `.invalid` top-level domain can never receive mail, RFC 2606); the app treats such emails as "no email". | Satisfies Better Auth without sending mail to a made-up address. |
| 2026-10-10 | UUID v7 ids come from the `uuid` package (`$defaultFn` in Drizzle, and Better Auth's `advanced.database.generateId`). | Postgres 17 has no built-in `uuidv7()`; generating in the app works the same locally, in CI and on Supabase. |
| 2026-10-10 | `shops.slug` format is also enforced by a database `CHECK` constraint (`^[a-z0-9-]{3,30}$`); reserved words are checked in the app. `shops.owner_id` uses `ON DELETE RESTRICT`; member, counter and subscription rows cascade when a shop is deleted. | A bad slug can never be saved by any code path. A user can't be deleted while they still own a shop (no orphaned shops). |
| 2026-10-10 | CI runs `pnpm db:migrate` before `pnpm check`. Staging (Supabase) migrations are run by hand for now with `DATABASE_URL=<staging> pnpm db:migrate`. | Integration and E2E tests need the tables. Automatic production migrations get their own design before launch. |
| 2026-10-11 | Schema files are one file per table (`users.ts`, `shops.ts`, `shop-members.ts`...) rather than one per domain (SPEC 4). | Small files are easier to read and review, and each table can be added in its own commit. `index.ts` re-exports them all, so imports don't change. |
| 2026-10-13 | Tenancy uses one login (the table owner) plus a `NOLOGIN` role `apekade_app` without `BYPASSRLS`. `withShop()` runs `set_config('app.shop_id', id, true)` and `SET LOCAL ROLE apekade_app` inside a transaction, so RLS applies. `apekade_app` only has grants on tenant tables (not `users`/`sessions`). | SPEC 5.6 requires a role that can't bypass RLS. Switching roles inside the transaction needs no second password or connection string, works the same locally, in CI and on Supabase, and both settings reset at commit, which is safe with the transaction pooler. |
| 2026-10-13 | Code outside `withShop` (Better Auth, creating a shop, platform admin, looking up a shop by slug) uses the owner connection, which RLS does not restrict. | These run before a shop is known or across shops. Keeping them few and in known places is the trade-off; tenant data (products, orders, customers) is only queried through `withShop`. |
| 2026-10-13 | RLS policies call `app_current_shop_id()`, which turns the `app.shop_id` setting into a uuid, or NULL when unset; NULL matches no rows. | One definition for every policy; a missing shop context fails closed (sees nothing) instead of erroring or seeing everything. |
| 2026-10-13 | Integration tests run against the local/CI Postgres with random-suffix fixtures and clean up after themselves; `rls-coverage.test.ts` fails if any table with a `shop_id` lacks RLS, a policy or a grant. `pnpm check` now needs `docker compose up -d`. | SPEC 13 requires real-Postgres isolation tests. The coverage test stops a future table (products, orders) from shipping without RLS. |
| 2026-10-14 | `vitest.config.mts` uses `process.env.DATABASE_URL` when set, otherwise the local Docker URL. | Lets integration tests run against a throwaway database (or CI's) without editing config. |
| 2026-10-15 | Adopted the v0 home page redesign (dark ink background, clay maroon `#8F3D2F`, citrus orange `#F6A23A`) after review: hard-coded strings moved to `messages/en.json`, text contrast raised to ≥ 4.5:1, header link made a 44 px tap target, the sample "orders" card labelled "Example". SPEC 11 tokens updated to match. | The founder preferred this look. AI-generated code is treated like any other contribution: it must pass the same rules (i18n, accessibility, formatting, tests) before merging. |
| 2026-10-16 | SMS providers implement `SmsProvider` (`src/server/providers/sms/types.ts`) and return `{ ok: true } \| { ok: false, error }` instead of throwing. `getSmsProvider()` uses Text.lk when `TEXTLK_API_KEY` is set, otherwise the console provider; in production without a key it logs a warning. | Sending fails for ordinary reasons (credit, network), which callers must handle. Staging can run without an SMS account; before launch the key must be set (add to the M6 launch checklist). |
| 2026-10-16 | Text.lk adapter: `POST https://app.text.lk/api/v3/sms/send`, Bearer token, recipient without "+", `type: "plain"`, 10 s timeout; message id read from `uid` or `data.uid` (the docs' example is ambiguous). | Matches https://text.lk/docs/send-sms/ as of 2026-10-15. |
| 2026-10-16 | Phone numbers in logs go through `maskPhone()` (`+9477•••4567`), including the development console SMS provider. | CLAUDE.md: never log buyer phone numbers; keeping the habit everywhere avoids leaks when code is copied. |
